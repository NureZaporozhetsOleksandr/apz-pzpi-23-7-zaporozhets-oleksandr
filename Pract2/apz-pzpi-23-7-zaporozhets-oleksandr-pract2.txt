3 ОПИС ВИКОНАНОЇ РОБОТИ
     Загальні відомості про онлайн-магазин Rozetka
     Rozetka є однією з найвідоміших українських e-commerce платформ, що поєднує функції онлайн-магазину та маркетплейсу. Система надає користувачам можливість переглядати каталог товарів, виконувати пошук і фільтрацію, додавати товари до кошика, оформлювати замовлення, здійснювати оплату, обирати доставку та отримувати інформацію про стан виконання замовлення. Для продавців платформа може надавати інструменти керування товарами, цінами, залишками та замовленнями, а для адміністраторів — засоби контролю, модерації та підтримки якості роботи системи.
     Необхідність складної архітектури для e-commerce платформи
     Великий онлайн-магазин не може ефективно функціонувати як проста програмна система без чіткого розділення відповідальності між компонентами. Кількість користувачів, обсяг каталогу товарів, інтенсивність пошуку, оформлення замовлень, інтеграції з платіжними та логістичними сервісами створюють значне навантаження на систему. Саме тому для такої платформи необхідна архітектура, яка дозволяє масштабувати окремі частини системи, ізолювати бізнес-логіку та забезпечувати стабільність роботи під час пікових навантажень.
     Архітектурний стиль системи
     Архітектуру онлайн-магазину Rozetka доцільно розглядати як клієнт-серверну, багаторівневу, модульну систему з ознаками мікросервісної та подієво-орієнтованої архітектури. Клієнт-серверний підхід передбачає взаємодію вебінтерфейсу або мобільного застосунку із серверною частиною через HTTP/HTTPS та API. Багаторівневість проявляється у відокремленні інтерфейсу користувача, серверної логіки, бізнес-сервісів, рівня зберігання даних та інфраструктурних компонентів. Модульність дозволяє виділяти окремі підсистеми, такі як каталог товарів, пошук, кошик, замовлення, платежі, доставка та сповіщення.
     Основні компоненти системи
     У межах роботи було розглянуто високорівневу компонентну схему онлайн-магазину Rozetka. До клієнтського рівня належать Web UI, Mobile App та Admin Panel. Центральною точкою входу для запитів є API Gateway або Web Backend, який приймає запити від клієнтів, виконує маршрутизацію та передає їх відповідним сервісам. Бізнес-рівень представлений сервісами каталогу товарів, пошуку і фільтрації, користувачів та авторизації, кошика, замовлень, платежів, доставки й сповіщень. Інфраструктурний рівень включає бази даних, кеш або CDN, а також черги повідомлень і логування.
     Клієнтський та серверний рівні
     Клієнтський рівень відповідає за взаємодію користувача із системою. Він включає сторінки каталогу, картки товарів, кошик, особистий кабінет та інші елементи інтерфейсу. Серверний рівень обробляє запити користувачів, реалізує бізнес-логіку товарів, кошика, замовлень і платежів, виконує авторизацію, взаємодіє з базами даних та зовнішніми сервісами. Таке розділення дозволяє незалежно розвивати інтерфейс і серверну логіку, а також спрощує масштабування системи.
     Взаємодія компонентів під час оформлення замовлення
     Процес оформлення замовлення демонструє взаємодію кількох підсистем. Спочатку користувач знаходить товар через каталог або пошук, після чого додає його до кошика. Під час оформлення замовлення система перевіряє актуальність даних, наявність товару та обчислює підсумкову вартість. Сервіс замовлень створює запис про замовлення та передає дані до платіжного модуля. Після підтвердження оплати ініціюється доставка, а сервіс сповіщень повідомляє користувача про стан замовлення. Такий сценарій підтверджує необхідність чітко організованої взаємодії між компонентами.
     Масштабованість та надійність
     Для забезпечення стабільної роботи онлайн-магазину важливими є механізми масштабованості та надійності. Масштабованість може досягатися за рахунок балансування навантаження, горизонтального масштабування окремих сервісів, кешування частих запитів та використання CDN для статичних ресурсів. Надійність забезпечується реплікацією баз даних, резервним копіюванням, чергами повідомлень, моніторингом, логуванням та дублюванням критичних компонентів. Такі підходи дозволяють системі витримувати пікові навантаження та швидко відновлюватися після збоїв.
     Приклади API та інтеграцій
     У роботі розглянуто приклади API-запитів, які можуть використовуватися в архітектурі онлайн-магазину. Запит GET /api/products?query=iphone може застосовуватися для пошуку товарів, POST /api/cart/items — для додавання товару до кошика, POST /api/orders — для створення замовлення, GET /api/orders/{id} — для отримання інформації про замовлення, а POST /api/payments/checkout — для ініціації оплати. Також було розглянуто інтеграції з платіжними сервісами, службами доставки, сервісами сповіщень та інструментами для продавців маркетплейсу.
     Приклад програмної реалізації
     Практична частина роботи містить спрощений приклад програмної реалізації API-обробника створення замовлення та сервісного рівня. API-обробник приймає HTTP-запит, отримує дані користувача, список товарів та адресу доставки, після чого передає обробку до сервісів кошика, замовлень і сповіщень. Сервісний рівень координує збереження замовлення, підготовку оплати та створення доставки. Такий приклад демонструє принцип розділення відповідальності між API-рівнем, бізнес-логікою та зовнішніми підсистемами.
     Переваги та обмеження архітектури
     До переваг розглянутої архітектури належать гнучке масштабування, чітке розділення відповідальності, зручна інтеграція зовнішніх сервісів, краща підтримуваність великої платформи та можливість незалежного розвитку модулів. Водночас така архітектура має певні обмеження: складнішу інфраструктуру, потребу в моніторингу та логуванні, ризики збоїв між сервісами, складніше тестування розподілених сценаріїв та вищі витрати на підтримку.

4 ВИСНОВКИ
     У ході виконання роботи було розглянуто архітектуру онлайн-магазину Rozetka як приклад складної сучасної e-commerce платформи. Проаналізовано її призначення, основні функції, категорії користувачів та вимоги до продуктивності, масштабованості й надійності.
     Було визначено, що архітектура такої системи може бути описана як клієнт-серверна, багаторівнева, модульна система з ознаками мікросервісної та подієво-орієнтованої архітектури. Розглянуто основні компоненти системи: клієнтський рівень, API Gateway або Web Backend, бізнес-сервіси, бази даних, кеш, CDN, черги повідомлень та засоби логування.
     Також було проаналізовано взаємодію компонентів під час оформлення замовлення, що дозволило показати роль каталогу, пошуку, кошика, замовлень, платежів, доставки та сповіщень у загальному бізнес-процесі. Окремо розглянуто механізми масштабування та забезпечення надійності системи.
     У результаті виконання роботи було сформовано розуміння принципів архітектурного аналізу великих вебсервісів та значення модульного підходу для побудови підтримуваних, масштабованих і відмовостійких програмних систем. Представлена архітектура є аналітичною моделлю високого рівня та демонструє типові принципи побудови великих онлайн-магазинів і маркетплейсів.
