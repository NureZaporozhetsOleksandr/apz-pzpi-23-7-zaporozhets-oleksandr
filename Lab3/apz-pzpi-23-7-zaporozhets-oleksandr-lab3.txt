     1. Мета роботи
     Метою лабораторної роботи є розробка front-end частини програмної системи, яка забезпечує роботу клієнтів у web-режимі, взаємодіє з backend-сервером через REST API та надає окремий набір функцій для звичайних користувачів і адміністраторів відповідно до ролей у системі.
     У межах роботи реалізовано web-застосунок WorkTime Monitor Web для системи обліку робочого часу. Застосунок дозволяє авторизувати користувача, фіксувати початок і завершення робочого дня, працювати з перервами, переглядати історію, статистику, графік, відсутності, а також виконувати адміністративні операції з користувачами, звітами та аудитом.
     2. Короткий опис системи
     Система WorkTime Monitor призначена для цифрового обліку робочого часу співробітників. Вона дає змогу фіксувати робочі події, контролювати перерви, переглядати статистику за період, вести записи відсутностей та аналізувати дії користувачів через журнал аудиту.
     У лабораторній роботі використано backend, реалізований у попередньому семестрі з дисципліни «Аналіз та рефакторинг коду». Серверна частина побудована на Node.js та Express, використовує SQLite-базу даних AtarkLabaDB.db і надає REST API. У межах цієї лабораторної роботи було створено web-клієнт, який працює з цим backend через HTTP-запити та JWT-авторизацію.
     Загальна структура системи містить браузер користувача, frontend web-застосунок, API-клієнт, backend-сервер, контролери, механізм авторизації, базу даних SQLite та Swagger UI для перевірки API.
     3. Прийняті інженерні рішення
     Для реалізації web-застосунку обрано стек HTML, CSS та JavaScript без використання складних frontend-фреймворків. Таке рішення зменшує складність розгортання, спрощує демонстрацію роботи у браузері та дозволяє зосередитися на взаємодії клієнта з backend-сервером.
     Клієнтська частина має модульну структуру. Файл index.html відповідає за HTML-структуру сторінок, файл styles.css визначає зовнішній вигляд інтерфейсу, app.js містить основну логіку роботи web-клієнта, api.js інкапсулює всі HTTP-запити до backend, а i18n.js відповідає за локалізацію українською та англійською мовами.
     Авторизація реалізована через JWT-токен. Після успішного входу backend повертає токен, який зберігається у localStorage. Під час подальших запитів модуль api.js додає цей токен до заголовка Authorization. Для отримання повної інформації про користувача після входу web-клієнт додатково викликає endpoint /api/auth/me.
     Розмежування доступу реалізовано за ролями Employee та Admin. Звичайний співробітник отримує доступ до функцій фіксації робочого часу, історії, статистики, відсутностей і графіка. Адміністратор додатково отримує доступ до керування користувачами, зміни ролей, блокування та розблокування акаунтів, формування звітів і перегляду журналу аудиту.
     Для запуску web-застосунку передбачено роздачу frontend через backend за адресою /app. Це дозволяє запускати весь проєкт через один сервер Node.js і зменшує ризик помилок CORS або перезавантаження сторінки через зміну SQLite-файлу.
     Для локалізації реалізовано перемикання мов UK/EN. Статичні тексти мають атрибути data-i18n, а динамічні елементи, які формуються JavaScript-кодом, оновлюються через функцію refreshLanguageUI. Це дозволяє перекладати не лише HTML-розмітку, а й кнопки, статуси, таблиці, повідомлення та значення часу.

     6. Взаємодія компонентів web-застосунку
     Взаємодія компонентів побудована за клієнт-серверною архітектурою. Користувач працює з інтерфейсом у браузері. HTML-сторінка завантажує стилі та JavaScript-модулі, після чого app.js відповідає за логіку сторінок і реакцію на дії користувача.
     Коли користувач натискає кнопку або відправляє форму, app.js викликає відповідний метод api.js. Модуль api.js формує HTTP-запит до backend, додає заголовок Content-Type та, якщо користувач авторизований, заголовок Authorization із JWT-токеном.
     Backend-сервер Express приймає запит, перевіряє токен за допомогою middleware, визначає роль користувача та передає запит до відповідного контролера. Контролер виконує SQL-операції з SQLite-базою даних і повертає відповідь у форматі JSON. Після отримання відповіді frontend оновлює потрібну частину інтерфейсу без перезавантаження сторінки.
СценарійПослідовність взаємодіїАвторизаціяindex.html -> app.js -> api.js -> POST /api/auth/login -> JWT -> GET /api/auth/me -> відображення ролі.Фіксація часуКнопка дії -> app.js -> api.js -> POST /api/time-entries/... -> SQLite -> оновлення історії та статистики.АдмініструванняАдмін-вкладка -> api.js -> /api/admin, /api/users, /api/audit -> перевірка ролі Admin -> таблиці користувачів і аудиту.ЛокалізаціяКнопка EN/UK -> i18n.js -> оновлення data-i18n -> app.js оновлює динамічні тексти.BackupДані поточної сесії -> JSON -> завантаження файлу або імпорт JSON у web-інтерфейс.Таблиця 6.1 — Взаємодія компонентів web-застосунку
